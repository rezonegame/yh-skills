# Comment Iteration Loop

> 用途：成稿预览后处理用户修改意见。目标是轻量迭代，不把每次反馈都变成从 Step 0 重跑。

## 反馈归类

收到反馈后，先归类再动手：

| 类型 | 例子 | 回到哪里 |
|---|---|---|
| 文案 | 改标题、换措辞、删一句话 | 当前页修改 + Step 7 QA |
| 视觉 | 颜色、字号、留白、图片裁切 | Step 4 / 当前页修改 + 视觉 QA |
| 结构 | 增删页、换顺序、拆合页 | Step 3-C 页型覆盖检查 |
| 事实数据 | 数字、来源、名称、日期错误 | Step 1-C 事实核查 |
| 页序 | 调整章节顺序或转场 | Step 3-C + Step 5 节奏规划 |

## 执行方式

1. 汇总反馈，不要逐条立即打断制作。
2. 合并同类项，避免一页被重复改多次。
3. 小改只改受影响页面；结构大改才回到大纲。
4. 每轮修改后重新执行受影响路径的 P0/P1 QA。
5. Path C/D/E 的视觉或结构改动后，重新跑截图 QA 和 contact sheet。

## 变更摘要

每轮迭代后给用户一个短摘要：

```text
本轮已处理：
- 文案：第 3、5 页标题重写
- 视觉：统一图表页间距，修复第 6 页文字溢出
- 结构：将风险页提前到结论前

已重新检查：P0 通过；contact sheet 已更新。
```

## 不要做的事

- 不要因为一个视觉小改重跑完整 Step 0-4。
- 不要静默改事实数据；事实修正必须有来源或用户明确给定。
- 不要把用户反馈分散在脑中；重要项目应写入项目记录。
- 不要在 P0 未通过时告诉用户“基本完成”。
