# Local Asset Registry

`references/meta/asset-registry.json` is generated by:

```bash
python scripts/build_asset_registry.py
```

This is the native asset discovery layer after absorbing upstream materials into `yh-slides`. It indexes local assets by use, not by upstream repository layout.

## Main Asset Families

| Family | Local path | Typical route |
|---|---|---|
| Core seeds | `assets/seeds/` | Path A/C/D |
| Runtime fonts/JS/CSS | `assets/vendor/` | HTML and PPTX tooling |
| Screenshot backgrounds | `assets/screenshot-backgrounds/` | Screenshot framing |
| Native PPTX charts/icons/layouts | `templates/charts/`, `templates/icons/`, `templates/layouts/` | `2A-S / Path S` |
| HTML themes/layouts/full decks | `templates/html-decks/html-ppt/` | `2D`, `2D-P` |
| Magazine/Swiss HTML seeds | `templates/html-decks/guizang/` | `2D / Path C` |
| Bento editable deck shell | `templates/html-decks/bento/` | `2D-B / Bento Deck` |
| Tosea local template previews | `templates/tosea/` | Style discovery across presentation routes |
| Wanghong handwritten HTML system | `assets/wanghong/` | Handwritten academic `2D / Path C-D` |
| Template Fill package | `scripts/template_fill_pptx.py`, `scripts/template_fill_pptx/` | `2A-T` |

## Schema

Each asset entry includes:

| Field | Meaning |
|---|---|
| `id` | Stable local identifier |
| `type` | Asset category, such as `html-theme`, `chart-template`, `script` |
| `path` | Path relative to the `yh-slides` root |
| `route_hint` | Suggested `yh-slides` route |
| `tags` | Search/recommendation tags |
| `source.origin` | Original source: `yh-slides`, `ppt-master`, `guizang-ppt-skill`, `html-ppt-skill`, or `bento` |
| `source.commit` | Upstream commit when applicable |
| `source.license` | License/provenance class |

## Usage Rules

- Use this registry in Step 4 when recommending local templates/assets.
- Show only 2-3 recommended assets by default.
- Read the full registry only when the user asks to browse all templates or when a path-specific selector needs it.
- Never let asset browsing bypass Step 0 intent discovery, outline confirmation, design direction, sample-page checkpoint, or P0-P3 QA.
