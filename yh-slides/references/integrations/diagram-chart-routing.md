# Diagram & Chart Routing

> 用途：当原始素材包含数据、流程、系统关系、组织结构或时间线时，先判断是否应该转成图表 / 示意图，而不是直接做成普通文字页。

## 1. 先判断是否需要图

出现以下任一情况，优先考虑图表或结构图：

- 有数字比例、份额、构成、预算、用户分布。
- 有按时间变化的数据、里程碑、版本演进。
- 有多个类别之间的比较、排名、差异。
- 有流程、审批、生产链路、用户旅程。
- 有系统组件、层级、模块、依赖关系。
- 有组织分工、角色边界、责任矩阵。

如果一页里没有明确关系，只是观点解释或故事叙述，不要强行图表化。

## 2. 数据图表选择

| 数据意图 | 默认图表 | 适合表达 | 避免 |
|---|---|---|---|
| 占比 / 构成 | donut | 市场份额、预算结构、用户来源 | 超过 5 个主要分类 |
| 时间序列 | line | 增长、趋势、周期、版本指标 | 只有 2 个时间点 |
| 类别对比 | bar | 不同产品、渠道、地区、方案比较 | 类别名过长且无排序 |
| 价值拆解 | waterfall | 收入桥、成本桥、利润变化 | 无正负增减逻辑 |
| 价格 / OHLC | candlestick | 股票、加密资产、交易价格 | 非金融价格场景 |
| 单个关键数字 | stat card | KPI、里程碑、核心结论 | 多个数字堆在同一页 |

规则：先确定要表达的比较关系，再选图表；不要因为图表好看而反推内容。

## 3. 结构图选择

| 内容结构 | 默认图示 | 适合表达 |
|---|---|---|
| 普通流程 | flowchart | 从开始到结果的步骤链路 |
| 跨角色流程 | swimlane | 多部门、多角色、多系统协作 |
| 系统组件关系 | architecture | 前端、后端、数据、第三方服务 |
| 分层模型 | layer-stack | 技术栈、能力层、战略层级 |
| 时间进展 | timeline | 路线图、历史演进、项目计划 |
| 二维分类 | quadrant | 价值/难度、风险/收益、成熟度矩阵 |
| 状态转换 | state-machine | 生命周期、审批状态、用户状态 |
| 层级归属 | tree | 组织结构、分类体系、目录结构 |
| 集合重叠 | venn | 能力交集、用户群重叠、定位差异 |

## 4. 幻灯片排版原则

- 一页最多一个核心图。图是主角，文字只负责解释结论。
- 图表页标题必须是结论型标题，例如“高端用户贡献了 62% 的复购”，不要写“用户来源分析”。
- 正文只保留图表读法、关键注释、数据来源；不要把图里的每个数字再抄一遍。
- 如果图表需要超过 6 个系列、8 个节点或 10 个步骤，拆成多页。
- Path B 图片型页面里不要让 AI 直接生成复杂可读图表；复杂数据图表优先 Path A / C / D，用 HTML/SVG/CSS 手工构建。

## 5. 逐页大纲写法

在 Step 1 的逐页大纲里，`Visual type` 应明确写出图表意图：

```text
Title: 企业客户增长主要来自北美大客户续约
Key points:
- 北美续约收入占新增 ARR 的 48%
- SMB 新客增长放缓
- 下一步应强化大客户成功团队
Visual type: stacked bar，按区域拆分新增 ARR；右侧 1 个 stat card 强调 48%
```

如果输入只是普通叙事内容，`Visual type` 可以写为 editorial text / quote / image-led layout，不需要强制套图表。
