# Workspace Protocol

This reference expands the operational protocol for `yh-local-knowledge`.

## Lifecycle

```text
Uninitialized folder
  -> Initialized workspace
  -> Source sync (with format normalization)
  -> Source map
  -> Extraction menu
  -> Candidate package
  -> User review
  -> Trusted assets
  -> Lint (health check, required before export)
  -> Export
  -> Incremental sync
  -> (feedback / compounding loop back to Candidate package)
```

## Status Values

Use these file statuses in `manifest.json`:

- `new`: discovered but not processed.
- `indexed`: metadata and available content have been indexed.
- `indexed_metadata_only`: recorded, but content extraction is not available.
- `changed`: hash or mtime changed since last sync.
- `deleted`: file was present before but no longer exists.
- `failed`: attempted processing failed.
- `unchanged`: no change since last sync.

Use these candidate/asset statuses:

- `candidate`: generated by the agent, not yet trusted.
- `verified`: approved by the user.
- `rejected`: rejected by the user.
- `uncertain`: user or agent marked it as needing more evidence.
- `deprecated`: superseded by a newer asset or invalidated source.
- `needs_review`: source changed or conflict found.

## Naming

Use predictable IDs:

- Source: `src_001`
- Candidate: `cand_001`
- Asset: `asset_001`
- Export: `export_YYYYMMDD_HHMM_target`

Use filesystem-safe slugs for filenames, but preserve readable Chinese titles inside files.

## Minimal Commands For An Agent

The skill can be executed conversationally. If implementing CLI later, map these actions:

```text
knowledge init
knowledge sync
knowledge map
knowledge menu
knowledge extract --package concept
knowledge review
knowledge export --target agent-workspace
```

## Review Gate

Before saving to `可信资产/`, present each candidate or candidate group with:

1. Title
2. Short content
3. Source evidence
4. Confidence or uncertainty notes
5. Suggested action

Acceptable user decisions:

- Confirm
- Confirm with edits
- Reject
- Mark uncertain
- Split
- Merge

## Incremental Sync

On every sync:

1. Recalculate source inventory.
2. Detect added/changed/deleted files.
3. Update `manifest.json`.
4. If sources changed, identify candidates/assets referencing changed source IDs.
5. Mark affected candidates/assets as `needs_review` or list them in `state.json`.
6. Regenerate source map sections that depend on changed files.

## Source Citation

Prefer precise citations:

```text
src_001#page=12
src_002#heading=核心概念
src_003#chunk=014
```

If page/heading/chunk is unavailable, cite only `src_001` and state that precise location is unavailable.
