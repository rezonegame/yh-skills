# PDF 处理备注

处理 PDF 前先读本文件。PDF 是最常见也最容易翻车的格式。

## PDF 的三种类型，处理方式不同

1. **文本型 PDF**（最常见）：markitdown/pdftotext 能直接抽出文字。正常处理。
2. **扫描型 PDF**（图片化）：文字抽不出来，全是空白或乱码。需要 OCR。检测信号：抽出来的文本远少于页数应有的字数，或全是空白。
3. **混合型 PDF**：部分文本部分扫描。可能抽出一部分，剩下的需要 OCR。

## 表格处理

PDF 里的表格是老大难。markitdown 默认尽力保留表格结构，但复杂表格（合并单元格、跨页表格）可能错位。

- 简单表格：markitdown 通常能转成 markdown 表格。
- 复杂表格：如果转出来错位严重，标注"该表格结构复杂，建议用户确认"，不要硬猜。
- 跨页表格：可能在每页重复表头，归一化时会断开。提取时要把分散的部分拼回完整表格。

## 大 PDF 分页

超过 ~50 页的 PDF：
- 用 pdftotext 的 `-f N -l M` 分页抽取（先转整本，再 grep/局部读）。
- 不要一次性把整本 PDF 塞进上下文。先转出 markdown，再用渐进式检索（grep + offset/limit）。

## 检测信号：什么时候该提示用户

- 抽出来空白 → 可能是扫描件，提示"此 PDF 似乎是扫描件，需要 OCR 工具才能提取文字"。
- 抽出来乱码 → 可能是特殊编码或字体嵌入问题，提示用户。
- 抽出来明显不全（100 页只抽出 2 页文字）→ 可能是图片型 PDF。

遇到这些情况，在 source-map 和候选里如实标注，不要假装读到了内容。

## OCR 降级路径

如果 markitdown 抽不出来且判定是扫描件：
1. 检查是否有 `markitdown-ocr` 或 OCR 工具（如 `pytesseract`）。
2. 有则对 PDF 转图片后 OCR。
3. 没有则标 `fallback_metadata_only`，提示用户"该扫描件需 OCR 工具，当前环境无法提取"。

## 不要做的事

- 不要对二进制 PDF 直接 grep（先转 markdown）。
- 不要假设 PDF 页码和内容对应（排版 PDF 的"页"可能和逻辑章节不对应）。
- 不要把整本 PDF 一次性读进上下文（用归一化后的 markdown 分段读）。
